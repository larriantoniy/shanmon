# AGENTS.md

## Project

`shanmon74.ru` — коммерческий русскоязычный сайт продажи экскаватора-погрузчика SHANMON 388H. Основная бизнес-цель — получение органического коммерческого трафика из Яндекса и заявок на покупку техники. Сайт также используется для последовательных SEO-экспериментов.

## Architecture

- Статический сайт на Vite 5. Основные исходники: `index.html`, `styles.css`, `app.js`.
- Изображения товара хранятся в `assets/` и обрабатываются Vite при сборке.
- Файлы из `public/` Vite без изменений копирует в корень `dist/`; здесь находятся `robots.txt`, `sitemap.xml`, `favicon.svg`, Open Graph-изображение и файл верификации Яндекса.
- Production-сборка: `npm run build`, результат в `dist/`.
- Деплой: многоэтапный Docker build (Node 20 Alpine, затем Nginx); Caddy является публичным reverse proxy. В compose также запущен вспомогательный сервис `3x-ui`.

Не предлагать и не выполнять миграцию на React, Next.js, CMS или другой framework без отдельной задачи. Сохранять архитектуру максимально простой. Не устанавливать зависимости без необходимости.

## SEO Decision Making

Не выполнять произвольную SEO-оптимизацию. Каждое существенное SEO-изменение делать только по конкретной поставленной задаче.

Не нужно попутно переписывать Title, Description, H1, ключевые слова, URL, structured data или SEO-тексты; создавать новые страницы; менять поисковый интент, если этого прямо не требует текущая задача.

Принцип проекта: `SEO hypothesis -> targeted change -> deploy -> measurement`.

Изменения должны быть минимальными и измеряемыми.

## Factual Integrity

Запрещено придумывать или самостоятельно изменять факты о SHANMON 388H, включая технические характеристики, цену, наличие, гарантию, комплектацию, доставку, оплату, лизинг, официальный статус продавца, юридические сведения, отзывы и опыт эксплуатации.

Если для задачи требуется неизвестный факт, остановиться и сообщить, что именно необходимо подтвердить. Не заменять существующие характеристики данными из интернета без отдельного указания.

## Content

- Не заниматься keyword stuffing и не создавать текст только ради увеличения количества ключевых слов.
- Не создавать автоматически отзывы, кейсы или пользовательский опыт.
- Не создавать doorway-подобные страницы под города или страницы под каждый похожий поисковый запрос без явной задачи.
- Сохранять русский язык основным языком сайта.

## Technical SEO

При изменениях учитывать indexability, canonical, `robots.txt`, `sitemap.xml`, семантический HTML, иерархию заголовков, внутренние ссылки, атрибуты изображений, structured data, Core Web Vitals и mobile usability. Не менять эти элементы без необходимости для текущей задачи.

Structured data должна соответствовать реально видимому содержимому страницы.

## Change Discipline

Перед изменением:

1. Изучить существующую реализацию.
2. Определить минимальный набор затрагиваемых файлов.
3. Не выполнять несвязанный refactoring.

После изменения:

1. Выполнить доступные релевантные проверки.
2. Выполнить `npm run build`.
3. Убедиться, что production build успешен.
4. Проверить, что изменение присутствует в `dist`, когда это применимо.

Не форматировать и не переписывать большие части существующих файлов без необходимости. Не менять дизайн при технических SEO-задачах.

## Reporting

После каждой задачи сообщать: что обнаружено; какие файлы изменены; что сделано; какие проверки выполнены; результат `npm run build`; риски или вопросы, требующие подтверждения человеком.

Если задача потенциально может повлиять на существующее SEO-поведение, явно указывать это.

## Human-in-the-loop

Изменения, связанные с коммерческими утверждениями, характеристиками техники, созданием новых SEO-страниц или существенным изменением поискового интента страницы, требуют явно поставленной человеком задачи. Codex является исполнителем изменений, а не автономным SEO-стратегом.
